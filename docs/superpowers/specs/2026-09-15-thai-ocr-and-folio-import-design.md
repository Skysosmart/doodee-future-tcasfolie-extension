# อ่านไทยให้ถูก + นำเข้าแฟ้ม TCASFolio — ดีไซน์

วันที่ 2026-09-15 · สถานะ: รออนุมัติก่อนลงมือ
ต่อจาก [`2026-08-24-pdf-import-design.md`](2026-08-24-pdf-import-design.md)

## โจทย์

ตัวนำเข้า PDF ทุกวันนี้ถูกออกแบบมาเพื่อ **เล่มพอร์ตที่ทำใน Canva** อย่างเดียว
พอเอา **ไฟล์ที่ TCASFolio ส่งออกเอง** เข้าไป มันพังสองชั้นพร้อมกัน:

1. **ภาษาไทยแตก** — รายละเอียดออกมาเป็น
   `ผลงานนวตกรรม PDlite ดานสขภาพและการแพทย ไดรบการคดเลอก…`
   (วรรณยุกต์และสระหายเกลี้ยง)
2. **ตัดชิ้นผิด** — ได้ร่าง 16 ชิ้นที่หัวข้อเป็น `ผลการอบรม : Completed`
   ส่วนหัวข้อจริง หน่วยงาน และวันที่ ถูกทิ้งทั้งหมด

ทั้งที่ไฟล์นั้นมีข้อมูลครบทุกช่องที่คลังต้องการ วางเป็นระเบียบกว่าเล่ม Canva เสียอีก

**เป้าหมาย:** ไฟล์แฟ้ม TCASFolio หนึ่งไฟล์ → ร่าง 16 ชิ้นที่ หัวข้อ/หมวด/ระดับ/
**หน่วยงาน**/**วันและเวลา**/ชั่วโมง/ผลรางวัล/**ลิงก์**/รายละเอียด ถูกต้องตามต้นฉบับ
และภาษาไทยในทุกเส้นทาง (รวมเล่ม Canva เดิม) ต้องดีขึ้น ไม่ใช่แค่ไฟล์นี้

## ไม่ทำ (non-goals)

- **ไม่ทำ OCR จากรูป** — ยังไม่ฝัง tesseract.js ไฟล์สแกนยังบอกว่าอ่านไม่ได้เหมือนเดิม
  (ตัดสินใจ 2026-09-15: +15MB ต่อส่วนขยาย แลกกับความแม่นไทยที่แย่กว่า text layer)
- **ไม่อัปเกรด pdf.js** — วัดแล้ว 4.10.38 กับ 5.4.149 ให้ผลเท่ากันเป๊ะ (empty 134 ชิ้นเท่ากัน)
  การอัปเกรดไม่ช่วยอะไรกับโจทย์นี้ จึงไม่เอาความเสี่ยงมาแลกฟรี ๆ
- **ไม่แก้ตรรกะ Canva เดิม** — `dropTwins` `keepIndexes` `dropOverlapping` `groupParagraphs`
  `segment` ไม่ถูกแก้ตรรกะ เทสต์เดิมทุกตัวต้องผ่านโดยไม่แก้ไฟล์เทสต์
- **ไม่เอาไฟล์อ้างอิงเข้า repo** — ไฟล์ที่ใช้วัดมีเลขบัตรประชาชน ที่อยู่ เบอร์โทร อีเมล
  fixture ทุกตัวเขียนขึ้นเองและใช้ชื่อสมมติ
- **ไม่ commit ให้เอง** — งานทั้งหมดทิ้งไว้ใน working tree

### 1. Chrome วาดวรรณยุกต์เป็น item แยกที่กว้างศูนย์

```
 idx   x        w       str
  26   103.90   4.30    "วั"      ← ปกติ
  ...
   2    74.21   5.17    "ว"
   3    79.30   0.00    "ั"       ← เครื่องหมาย กว้าง 0 พอดี
   4    79.38   0.00    " "       ← ช่องว่างขยะ กว้าง 1e-7…1e-4
   5    79.38   58.23   "ตกรรม PDlite"
```

`dropOrphanMarks` (ที่เขียนไว้ทิ้งเศษของ Canva) ลบชิ้นที่ 3 ทิ้ง → ไทยแตก

**ตัวแยกที่ใช้ได้จริง:** เศษของ Canva **มีความกว้าง** (fixture ในเทสต์เดิมคือ `w: 6`)
ส่วนเครื่องหมายของ Chrome **กว้าง 0 พอดีทั้ง 902 ชิ้น**

| กลุ่ม | ความกว้างที่วัดได้ |
|---|---|
| เครื่องหมายของ Chrome | **0 พอดี** (902/902 ชิ้น) |
| ช่องว่างขยะ | 1.15e-7 … **0.0375** |
| ช่องว่างจริงที่แคบที่สุด | **0.2760** |
| glyph ที่มองเห็นได้ที่แคบที่สุด | ไม่มีตัวไหนต่ำกว่า 0.276 |

→ ใช้เกณฑ์ **`w < 0.1`** ซึ่งอยู่กึ่งกลางช่องว่างระหว่างสองกลุ่ม เหลือระยะเผื่อราว 2.7 เท่าทั้งสองทาง

### 3. ตัวที่ "หายไป" ไม่ได้หาย — มันเป็นอักขระในเขต Private Use

ชิ้นที่ `getTextContent()` คืนมาแล้วดูเหมือนว่าง **ส่วนใหญ่ไม่ใช่ค่าว่าง** แต่เป็นรหัสในเขต
Private Use Area ซึ่งเป็นธรรมเนียมเก่าของฟอนต์ไทยบนวินโดวส์ ใช้เก็บ "รูปแปร" ของ
เครื่องหมายที่ต้องขยับตำแหน่งเมื่อไปอยู่บนพยัญชนะหัวสูง (ป ฟ ฝ) — Skia ส่งต่อรหัสพวกนี้มาตรง ๆ

พบ 206 ชิ้นในไฟล์อ้างอิง 7 รหัส และอ่านความหมายได้จากบริบทตรง ๆ:

```
ประจำป[U+F702] 2570      → ปี        วันเดือนป[U+F702]เกิด → ปีเกิด
แฟ[U+F706]มสะสมผลงาน     → แฟ้ม
ทางป[U+F710]ญญา          → ปัญญา     ป[U+F710]จจุบัน → ปัจจุบัน
ไดคะแนนเป[U+F712]น       → เป็น
```

**ตารางที่ใช้ ได้จากการวัดเทียบ `pdftotext` ไม่ใช่จากตำราที่จำมา** — ทำสคริปต์จับคู่บรรทัด
ของเรากับบรรทัดของ poppler แล้วนับคะแนนทีละตำแหน่ง ผลออกมาเอกฉันท์ทุกรหัส:

| รหัส | → | จำนวนที่วัดได้ |
|---|---|---|
| `U+F70A` | `่` U+0E48 | 83 (เอกฉันท์ 36/36 ที่จับคู่ได้) |
| `U+F70B` | `้` U+0E49 | 69 (เอกฉันท์ 33/33) |
| `U+F70E` | `์` U+0E4C | 27 (เอกฉันท์ 7/7) |
| `U+F702` | `ี` U+0E35 | 13 |
| `U+F706` | `้` U+0E49 | 10 |
| `U+F710` | `ั` U+0E31 | 3 |
| `U+F712` | `็` U+0E47 | 1 |

> **ตำราที่จำมาผิดสองช่อง** — ถ้าเชื่อตารางลอย ๆ จะได้ `U+F702`→`้` (ทำให้ `ปี` กลายเป็น `ป้`)
> และ `U+F712`→`ี` การวัดจริงจึงไม่ใช่พิธีกรรม แต่เป็นสิ่งที่กันข้อความเพี้ยนจริง ๆ

รหัสสามตัวที่พบมากที่สุดเรียงต่อกันเป็นช่วง `U+F70A`–`U+F70E` = `่ ้ ๊ ๋ ์` (U+0E48–U+0E4C)
ตามลำดับยูนิโค้ดพอดี ช่วง `U+F705`–`U+F709` และ `U+F700`–`U+F704` ก็เข้ากับโครงเดียวกัน
จึงเติมช่องที่เหลือของสามช่วงนี้ตามโครง **ส่วนรหัสนอกช่วงที่ไม่ได้วัด ห้ามเดา** (ดูกฎในหัวข้อ `pdfGlyphs.js`)

### 4. ที่ยังขาดจริง ๆ อยู่ใน `/ActualText`

Chrome หลอมวรรณยุกต์บางตัวเข้ากับพยัญชนะเป็น glyph เดี่ยว (contextual alternate)
ที่ไม่มีใน ToUnicode แล้วเขียนข้อความจริงไว้ใน marked content แทน:

```
/Span<</ActualText <FEFF0E1F0E49> >> BDC   ← "ฟ้"
  10.35 0 Td <0D> Tj   /F6 21 Tf   11.32 0 Td <04> Tj
EMC
```

`pdftotext` อ่านตรงนี้ จึงได้ไทยครบ · **pdf.js ไม่เคยส่งค่านี้ออกมา** — ยืนยันแล้วทั้ง
4.10.38 และ 5.4.149: `getTextContent({includeMarkedContent:true})` ให้แค่ `tag:"Span"`
และ `getOperatorList()` ให้ `["Span", null]` เนื้อความหายไปทั้งคู่
(pdf.js อ่าน ActualText เฉพาะจาก structure tree เท่านั้น ซึ่งไฟล์นี้ไม่ได้ใช้)

ตัวที่ขาดคือตัวที่ใช้บ่อยที่สุด: `่` ขาด 148/279 · `้` ขาด 115/278 · `ี` 46/180 · `ิ` 30/152

### 5. คำที่ parser ต้องจับ เคยเสียรูป — ข้อ 3 แก้ให้แล้ว

```
ระดับโรงเรยน/สถาบัน ไมมีคาใชจาย วันที่: 20–22 และ 24 ต.ค. 2568 (120 ชม.) · …
ลิงกแสดงผลงาน : https://pranakorn.co.th/
หมวด 4.4 · การอบรม / การเรยนเพิ่มทักษะอ่นๆ
```

หลังถอด PUA คำเหล่านี้กลับมาถูกทั้งหมด:

```
ระดับโรงเรียน/สถาบัน ไม่มีค่าใช้จ่าย วันที่: 20–22 และ 24 ต.ค. 2568 (120 ชม.) · …
ลิงก์แสดงผลงาน : https://pranakorn.co.th/
หมวด 4.5 · ผลงานสร้างสรรค์      ผลตอบรับ / รางวัล : …      ช่วงเวลา: 1 มี.ค. 2569 - ปัจจุบัน
```

**ถึงอย่างนั้น parser ก็ยังต้องเทียบคำแบบถอดเครื่องหมาย** — เป็นเกราะชั้นสอง เผื่อไฟล์จาก
ตัวสร้าง PDF อื่นที่ยังมีเครื่องหมายหาย การพึ่งข้อ 3 อย่างเดียวคือการฝากความถูกต้องของ
ตัวตัดชิ้นไว้กับตารางที่วัดมาจากไฟล์เดียว

### 6. โครงของแฟ้ม TCASFolio เป็นระเบียบและเดาได้

หลังซ่อมชั้น item แล้ว `buildRows` (tolerance 2) คืนแถวที่แยกหน้าที่กันชัดเจน
โดยเลขลำดับกับหัวข้อรวมมาในแถวเดียว และขนาดตัวอักษรเป็นตัวช่วยยืนยัน:

```
[h=10.2] หมวด 4.1 · รางวัล / เกียรติบัตร          ← หัวหมวด
[h=11.7] 1 I-NEW GEN AWARD 2026 และ SWU …          ← ลำดับ + หัวข้อ
[h= 9.0] ระดับชาติ ไมมีคาใชจาย วันที่: … · <หน่วยงาน>   ← แถวข้อมูล
[h= 9.8] ผลรางวัล / อันดับ : เหรยญทอง              ← ผลงาน
[h= 9.8] <รายละเอียด …>
[h= 8.6] หนา 5 / 10                                 ← ขยะประจำหน้า
```

`หมวด 4.1`–`4.5` เรียงตรงกับ `Model.FOLIO_SECTIONS` ที่มีอยู่แล้วเป๊ะ
(awards · projects · activities · trainings · creatives)

## ฟิลด์ใหม่ในคลัง

```
{ type, title, org, when, level, result, hours, link, detail, tags }
                      ^^^^                         ^^^^
```

- **`when`** — วันและเวลา เช่น `มกราคม-เมษายน 2569` · `24 พ.ค. 2569` · `1 มี.ค. 2569 - ปัจจุบัน`
  เก็บเป็นข้อความตามที่เขียนในเล่ม ไม่แปลงเป็น Date — ต้นฉบับมีทั้งช่วงคร่าว ๆ
  ทั้ง `ปัจจุบัน` และทั้ง `20–22 และ 24 ต.ค. 2568` ซึ่งไม่มีทางแปลงกลับได้โดยไม่ทำข้อมูลเพี้ยน
- **`link`** — ลิงก์แสดงผลงาน

`EXPORT_VERSION` **คงเป็น 1** — ฟิลด์ใหม่เป็นการเพิ่มล้วน ไฟล์ backup เก่าและคลังเก่า
โหลดได้เหมือนเดิม (`normalize()` เติม `""` ให้เอง แล้วเขียนกลับครั้งเดียวผ่านกลไก `changed` ที่มีอยู่)

### ทำไมต้องมี `when` จริง ๆ ไม่ใช่ยัดรวมใน `org`

ทุกวันนี้มีสามธรรมเนียมที่ขัดกันเองอยู่ในโค้ดเดียวกัน:

| ที่ | ทำอะไรกับวันที่ |
|---|---|
| `popup.html` | ช่องเดียวชื่อ `หน่วยงาน / ปี` |
| `content.js` | `splitOrg()` ตัด `"หน่วยงาน · วันที่"` กลับเป็นสองช่องตอนเติมฟอร์ม |
| `siteImport.js` | ยอมแพ้ เอา `วันที่ …` ไปแปะหัว `detail` (คอมเมนต์เขียนว่า "ส่วนขยายไม่มีช่องวันที่") |

`splitOrg()` เดาจาก `·` แล้วดูว่าท่อนท้ายมีตัวเลขไหม ซึ่งพังกับข้อมูลจริงในไฟล์อ้างอิง:
`Pranakorn Corporation Co., Ltd.` ไม่มี `·` เลย ส่วน `MakeX Thailand: Challenges 2025`
จะถูกอ่านว่าปีคือ `2025` ทั้งที่นั่นคือส่วนหนึ่งของชื่อ

`when` ทำให้ทั้งสามทางเก็บที่เดียวกัน และ `splitOrg()` เหลือหน้าที่เดียวคือรองรับของเก่า

## `pdfGlyphs.js` — ซ่อมชั้น item (ตรรกะล้วน มีเทสต์)

ไม่มี `chrome.*` ไม่มี DOM ไม่มี pdf.js

### `normalizeItems(items, spans)`

เดินตาม **ลำดับเดิมของ content stream** (ห้ามเรียงตาม x ตรงนี้ — ลำดับเดิมคือลำดับที่ถูกต้อง
ของภาษาไทยอยู่แล้ว การเรียงตาม x คือสิ่งที่ทำให้ `เกียรติ` กลายเป็น `เก ยรี`)

| ชิ้นที่เจอ | ทำ |
|---|---|
| `w ≥ 0.1` | เก็บเป็น item ปกติ |
| `w < 0.1` และเป็นตัวอักษร/เครื่องหมาย | ต่อท้าย item ก่อนหน้าที่อยู่แถวเดียวกัน (`\|Δy\| ≤ 2`) |
| `w < 0.1` และเป็น `" "` หรือ `""` | ทิ้ง (ขยะจากการถอยตำแหน่งของ Skia) |
| `w < 0.1` แต่ไม่มี item ก่อนหน้าในแถว | เก็บไว้เป็น item ของตัวเอง — ห้ามทิ้งเงียบ ๆ |

**ลำดับสำคัญ:** `normalizeItems` ต้องรันก่อน `dropOrphanMarks` และ `dropOverlapping` เสมอ
เพื่อไม่ให้สองตัวนั้นเห็นเครื่องหมายเปล่าของ Chrome — เทสต์ Canva เดิมจึงไม่ต้องแก้แม้แต่บรรทัดเดียว

### `unpua(text)` — ถอดรหัสเขต Private Use

แทนที่ `U+F700`–`U+F71F` ด้วยเครื่องหมายไทยจริงตามตารางในหลักฐานข้อ 3

**กฎเหล็ก: รหัสที่ไม่มีในตาราง ห้ามเดา** ให้ปล่อยอักขระนั้นไว้ตามเดิมแล้วนับจำนวนไว้
`import.js` เอาไปขึ้นเตือนในหน้าตรวจร่างว่า "อ่านบางตัวอักษรไม่ออก N ตัว"

ผู้ใช้เห็นตัวประหลาดในร่างแล้วแก้เองได้ แต่ถ้าเดาผิดเป็นวรรณยุกต์ที่ดูสมเหตุสมผล
จะไม่มีใครจับได้เลย — `ปี` ที่กลายเป็น `ป้` คือสิ่งที่เกิดขึ้นจริงตอนลองใช้ตารางจากตำรา

เรียกที่เดียวกับ `composeThai` คือระดับแถวหลัง join

### `composeThai(text)`

`ํ` + `า` → `ำ` (และสลับลำดับด้วย) **เรียกระดับแถวหลัง join เท่านั้น**
เพราะ `จ` `ํ` `า` มาเป็นคนละ item — ประกอบตอนยังเป็น item จะไม่เห็นคู่นี้
(วัดจริง: ประกอบผิดที่ได้ `ประจําป` ประกอบถูกที่ได้ `ประจำป`)

จุดเรียก: `buildRows()` หลัง `joinParts()` และใน `groupParagraphs()` หลังต่อย่อหน้า

## `pdfActualText.js` — เก็บเศษสุดท้าย (เฟสแยก มีประตูตัดสินใจ)

หลังข้อ 3 เหลือเครื่องหมายที่ขาดอีก 198 ตัว (13.1%) ซึ่งเป็นชิ้นที่ว่างจริง ๆ ไม่มีแม้แต่รหัส PUA
ทางเดียวที่เหลือคืออ่าน `/ActualText` จาก content stream เอง

**นี่เป็นเฟสสุดท้ายและแยกออกจากเฟสอื่นได้** — ถ้าไม่ทำ ระบบยังใช้งานได้ที่ 97.5%
และตัวตัดชิ้นทำงานถูกต้องครบ เพราะคำที่ parser ต้องจับกลับมาถูกหมดแล้วตั้งแต่ข้อ 3

### สิ่งที่ทำ

1. หา object ของหน้าจาก `page.ref` (`{num, gen}` ที่ pdf.js เปิดให้ใช้) ใน byte ดิบ
2. อ่าน `/Contents` (ref เดี่ยวหรือ array) แล้วคลายด้วย `DecompressionStream("deflate")`
   — มาตรฐานเว็บ มีทั้งในส่วนขยายและใน Node 18+ จึงเทสต์ด้วย `node --test` ได้
3. ไล่หา `/Span\s*<<\s*/ActualText\s*<([0-9A-Fa-f]+)>` **ตามลำดับ** ถอดเป็น UTF-16BE (ตัด BOM)
4. คืน `string[]` — ตัวที่ N คือ ActualText ของ Span ที่ N ในหน้านั้น

จากนั้น `pdfGlyphs.normalizeItems` จับคู่: Span ที่ N จาก
`getTextContent({includeMarkedContent:true})` ← ข้อความที่ N จากขั้นบน
แล้วแทนข้อความของกลุ่ม item ที่อยู่ในช่วง `beginMarkedContentProps` … `endMarkedContent` นั้น

### กฎความปลอดภัย (สำคัญกว่าตัวฟีเจอร์)

> **จำนวน Span ไม่เท่ากันเมื่อไหร่ ทิ้งทั้งหน้า** แล้วใช้ผลจาก `pdfGlyphs` ล้วน ๆ แทน

เช่นเดียวกับกรณี: ไฟล์ใส่รหัส · หา object ของหน้าไม่เจอ · object ถูกยัดอยู่ใน object stream ·
ฟิลเตอร์ไม่ใช่ FlateDecode · คลายไม่ออก — ทุกกรณีคืน `[]` เงียบ ๆ

**เหตุผล:** ข้อความที่ผิดแย่กว่าวรรณยุกต์ที่หาย ร่างที่ไทยไม่ครบผู้ใช้เห็นแล้วแก้เองได้
แต่ร่างที่คำถูกสลับไปอยู่ผิดที่ ผู้ใช้จะไม่ทันสังเกตแล้วมันจะไหลเข้าใบสมัครจริง

### งานชิ้นแรกของเฟสนี้คือพิสูจน์ว่าคู่กันได้จริง

ก่อนเขียนตัวแทนค่า ให้เขียนสคริปต์วัดก่อนว่า **จำนวน `Span` จาก pdf.js เท่ากับจำนวน
`/ActualText` ที่หาเจอในทุกหน้าของไฟล์อ้างอิงหรือไม่** ถ้าไม่เท่า ให้หยุด รายงาน
แล้วจบที่ 97.5% — ไม่ต้องดันต่อด้วยการเดา

## `pdfFolio.js` — อ่านแฟ้ม TCASFolio

### ตรวจว่าใช่ไฟล์นี้ไหม

แถวใดแถวหนึ่ง (หลังถอดเครื่องหมาย) ตรงกับ `หมวด 4.<เลข> ·` **และ** ท้ายแถวตรงกับชื่อหมวด
ที่รู้จักตัวใดตัวหนึ่ง → ใช้ `pdfFolio` · ไม่ตรง → ตกไปที่ `pdfText.segment` เดิม

### การเทียบคำ

ทุกคีย์เวิร์ดเทียบด้วย `PdfText.stripMarks()` ทั้งสองฝั่ง แล้ว **คืนค่าเป็นสตริงมาตรฐาน**
โดยเฉพาะ `level` ต้องคืนค่าที่ตรงกับ `Model.LEVELS` เป๊ะ ไม่งั้นตอนเติมฟอร์มจะหาตัวเลือกไม่เจอ

```
"ระดับโรงเรยน/สถาบัน"  --stripMarks-->  "ระดบโรงเรยน/สถาบน"
                                              │ ตรงกับ
Model.LEVELS[0] "ระดับโรงเรียน/สถาบัน" --stripMarks--> "ระดบโรงเรยน/สถาบน"
                                              ▼
                        คืน "ระดับโรงเรียน/สถาบัน"  (ค่ามาตรฐาน)
```

### เครื่องสถานะ (เดินทีละแถว ข้ามขอบหน้า — ชิ้นงานคาบหน้าได้)

| แถวที่เจอ | ทำ |
|---|---|
| `หมวด 4.N · …` | ปิดชิ้นที่ค้าง · ตั้ง `type` จาก N เทียบ `FOLIO_SECTIONS` (สำรอง: เทียบชื่อหมวด) · เข้าโหมดอ่านชิ้น |
| `หมวด 1\|2\|3 · …` | ปิดชิ้นที่ค้าง · ออกจากโหมดอ่านชิ้น (ข้ามหน้าประวัติ ปพ.1 เรียงความ) |
| `แฟ้มสะสมผลงาน · ประจำปี …` หรือ `หน้า N / M` | ทิ้ง (ขยะประจำหน้า) |
| `^(\d{1,2})\s+(.+)` และเลขตรงกับลำดับถัดไปของหมวด | ปิดชิ้นที่ค้าง · เปิดชิ้นใหม่ `title` = กลุ่มที่ 2 |
| ขึ้นต้นด้วยชื่อระดับ | แถวข้อมูล → แยกตามไวยากรณ์ข้างล่าง |
| `ผลรางวัล / อันดับ :` `สถานะการเข้าร่วม :` `ผลการอบรม :` `ผลตอบรับ / รางวัล :` | `result` |
| `ลิงก์แสดงผลงาน :` | `link` |
| อื่น ๆ | ต่อท้าย `detail` |

เงื่อนไข "เลขตรงกับลำดับถัดไป" กันหัวข้อที่ขึ้นต้นด้วยตัวเลขจริง ๆ ไม่ให้ถูกตัดหัวทิ้ง
และกันบรรทัดรายละเอียดที่บังเอิญขึ้นต้นด้วยเลขไม่ให้กลายเป็นชิ้นใหม่

### ไวยากรณ์ของแถวข้อมูล

```
metaRow := level [cost] [when] [hours] [ "·" orgs ]

level := หนึ่งใน Model.LEVELS            (เทียบแบบถอดเครื่องหมาย)
cost  := "ไม่มีค่าใช้จ่าย" | "มีค่าใช้จ่าย"   (ทิ้ง — คลังไม่มีช่องนี้)
when  := ("วันที่:" | "ช่วงเวลา:") ข้อความ
hours := "(" ตัวเลข "ชม." ")"             → เก็บเฉพาะตัวเลข
orgs  := ทุกอย่างหลัง "·" ตัวแรก
```

ตัดที่ `·` **ตัวแรก** ก่อน แล้วค่อยแกะ `when` กับ `hours` จากท่อนหน้า
เพราะชื่อหน่วยงานมีวงเล็บได้ (`(วช.)` `(SIIT)`) แต่ไม่มี `·`

เคสที่ไฟล์อ้างอิงบังคับให้รองรับ:

| แถวจริง | ผลที่ต้องได้ |
|---|---|
| `ระดับชาติ ไมมีคาใชจาย` | level เท่านั้น — `when` `org` `hours` ว่างหมด |
| `… มีคาใชจาย (48 ชม.) · Sirindhorn International Institute of Technology (SIIT)` | hours + org ไม่มีวันที่ |
| `… ชวงเวลา: 31 ส.ค. 2568 - ปจจุบัน` | when อย่างเดียว ไม่มีหน่วยงาน |
| `… วันที่: 20–22 และ 24 ต.ค. 2568 (120 ชม.) · คณะแพทยศาสตร…` | ครบสามอย่าง |
| `… วันที่: มกราคม-เมษายน 2569 · สำนักงานการวิจัยแห่งชาติ (วช.), สถาบันยุทธศาสตร…` | org เป็นรายการคั่นจุลภาค เก็บทั้งก้อน |

### สิ่งที่คืนออกมา

รูปร่างเดียวกับ `PdfText.toDrafts()` — `{ drafts, skipped }` เพื่อให้ `import.js`
ไม่ต้องรู้ว่าอ่านมาจากทางไหน ต่างกันแค่ `drafts` มี `org` `when` `hours` `result` `link` เติมมาแล้ว

## `pdfText.js` — เดาหน่วยงาน/วันที่ ในเล่ม Canva

ของเดิมไม่แก้ เพิ่มสองฟังก์ชันที่ `toDrafts()` เรียกต่อท้าย เหมือน `guessType`/`guessLevel` ที่มีอยู่

- **`guessWhen(text)`** — หาแบบแรกที่เจอ: `วันที่:`/`ช่วงเวลา:` → เดือนไทยย่อ/เต็ม + ปี
  → `dd/mm/yyyy` → ปี พ.ศ. (25xx) / ค.ศ. (20xx) เดี่ยว ๆ
- **`guessOrg(text)`** — วลีที่ขึ้นต้นด้วย `โรงเรียน` `มหาวิทยาลัย` `สถาบัน` `สำนักงาน`
  `บริษัท` `คณะ` `ศูนย์` `กอง` `สมาคม` `มูลนิธิ` `กรม` `กระทรวง` แล้วกินไปจนจบวลี

ทั้งคู่เดาผิดได้ และนั่นรับได้ — ค่าที่ได้ไปโผล่ในหน้าตรวจร่างซึ่งผู้ใช้แก้ก่อนบันทึกอยู่แล้ว
สิ่งที่รับไม่ได้คือเดาแล้วไปทับของที่อ่านมาตรง ๆ จึงเดาเฉพาะตอนช่องนั้นยังว่าง
